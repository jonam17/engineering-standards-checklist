# Exception and risk-acceptance register

Exceptions must be explicit, scoped, approved by an accountable risk owner, and time-bound. Do not use exceptions to waive obligations that cannot legally or contractually be waived.

| Exception ID | Requirement / control | Scope | Rationale | Risk | Compensating controls | Risk owner | Approver | Approval date | Expiry / review date | Closure evidence |
|---|---|---|---|---|---|---|---|---|---|---|
| | | | | | | | | | | |

## Review rules

- Reassess when the underlying risk, product, architecture, data, threat, or legal context changes.
- Expired exceptions must not be treated as approved.
- Record closure evidence when the requirement is implemented or the affected scope is retired.
